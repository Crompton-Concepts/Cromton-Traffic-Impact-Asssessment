## 2024-05-24 - Spatial Bounding Box Pre-filtering
**Learning:** The frontend JavaScript (app.js) processes large GeoJSON spatial datasets. Iterating over these datasets with expensive Haversine distance calculations is a performance bottleneck. Fast spatial pre-filtering (bounding box via dLat and dLon thresholds) significantly improves performance, but it must only be applied to bounded searches (e.g., `localCounterMatchRadiusMeters`) to avoid false negatives on global unbounded searches. Additionally, exact Earth radius calculations, ~1% padding, division-by-zero guards at the poles, and antimeridian wrapping handling are required to prevent edge-case bugs.
**Action:** When iterating over spatial data, implement a bounding box pre-filter before computationally expensive distance calculations. Calculate degrees dynamically (`R=6371000`), add ~1% padding, guard against division by zero (`Math.max(Math.abs(Math.cos(lat)), 0.0001)`), and handle antimeridian wrapping. Do not apply bounding box limits to unbounded searches (e.g., `findBestReferencePoints`).
